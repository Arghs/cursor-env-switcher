# Repository Guidelines

## Project Structure & Module Organization

This repository is a Cursor-compatible VS Code extension.

- `src/extension.ts` contains the extension activation code, status bar item, command registration, and workspace file operations.
- `src/envSwitcher.ts` contains pure env-mode detection and rename-plan logic.
- `src/envSwitcher.test.ts` contains unit tests for the pure switching logic.
- `dist/` is generated by TypeScript and should not be edited directly.
- `docs/superpowers/` contains design and implementation planning notes.

Keep IDE integration separate from file-switching rules so behavior can be tested without launching Cursor.

## Build, Test, and Development Commands

- `npm install` installs development dependencies from `package-lock.json`.
- `npm run compile` runs `tsc -p .` and emits compiled JavaScript into `dist/`.
- `npm test` compiles the project and runs Mocha tests from `dist/**/*.test.js`.

To run locally, open this folder in Cursor or VS Code and press `F5` to launch an extension development host.

## Coding Style & Naming Conventions

Use TypeScript with strict compiler settings. Follow the existing style:

- Two-space indentation.
- Double quotes for strings.
- Semicolons at statement ends.
- `camelCase` for variables and functions.
- `PascalCase` for TypeScript interfaces and type-like names when appropriate.

Prefer small, focused functions. Keep filesystem side effects in `extension.ts`; keep deterministic logic in `envSwitcher.ts`.

## Testing Guidelines

Tests use Mocha with Node `assert/strict`. Name test files as `*.test.ts` beside the code they verify.

Add tests for every new behavior in env detection, validation, or rename planning. For extension-host UI changes, keep pure logic covered in unit tests and manually verify the status bar in an extension development host.

Run `npm test` before submitting changes.

## Commit & Pull Request Guidelines

This folder currently has no git history. Use concise Conventional Commit-style messages going forward, for example:

- `feat: add env switch status bar item`
- `fix: block ambiguous env file state`
- `test: cover prod-to-dev switch plan`

Pull requests should include a short description, test results such as `npm test`, and notes for any manual Cursor verification. Link related issues when available. Screenshots are only needed for visible UI changes.

## Security & Configuration Tips

Do not commit real `.env`, `.env.dev`, or `.env.prod` files. Test env switching with dummy values only. The extension renames files in the first workspace folder, so verify the correct folder is open before manual testing.
